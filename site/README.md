# Штаб CS2 «Ушибу ногами»

Статический мини-сайт: план подготовки к первому матчу 30.09.2026, плейбуки по картам,
соперники, расписание лиги, регламент и отдельный кодекс командной игры.

## Как открыть

Просто двойной клик по `index.html` — всё работает с `file://`, интернет не нужен
(шрифты и логотип лежат в `assets/`).

Для разработки удобнее локальный сервер:

```bash
python3 -m http.server 8422
# → http://localhost:8422/
```

## Страницы

| Файл | Что внутри |
|---|---|
| `index.html` | Штаб: Обзор · Тренировки · Тактики · Соперники · Матчи · Регламент · Голосование |
| `pravila.html` | Кодекс: кто сколько освоил → 10 заповедей → 30 правил с фильтрами → лестница внедрения → 16 разборов → источники |

Разделы штаба живут в адресе: `index.html#/taktiki`, `#/matchi` и т.д. — можно кидать прямые ссылки,
работает кнопка «назад».

## Где править контент

Вся фактура вынесена из разметки в данные. Меняешь одну строку — обновляется везде
(обзор, роадмап, отсчёт, прогресс).

| Файл | За что отвечает |
|---|---|
| `assets/js/data.season.js` | Расписание тренировок и отметки о проведённых, слоты, протокол 120 минут, матчи, команды, голосование, роли, чеклист матч-дня, заметка «Ресурс до старта» (`meta.resourceNote`) |
| `assets/js/data.playbook.js` | Плейбуки по 7 картам: вето, дефолты T/CT, выходы, позиции, ротации, гранаты, чеклисты |
| `assets/js/data.rules.js` | 30 правил, заповеди, лестница внедрения, разборы, источники |

Дата первого матча — `SEASON.firstMatch.date`, от неё считается обратный отсчёт.

### Как отметить проведённую тренировку

Три правки в данных, всё остальное пересчитается само:

1. `data.season.js` → нужная сессия в `sessions`: добавить `done: true` и `doneDate: 'ГГГГ-ММ-ДД'`
   (фактическую дату — она может не совпасть с плановой). Сессия становится зелёной с галочкой,
   в роадмапе — «✓ проведена», «Ближайшая тренировка» перескакивает на следующую неотмеченную.
2. `data.playbook.js` → карта дня: `order: 'done'`; у остальных карт сдвинуть номера и текст
   приоритета. Карта уходит из списка «Приоритет карт» на Обзоре в плашку «… готова».
   В `data.season.js` → `polls.maps.rows` этой карте поставить `done: true` — появится чип «готова».
3. `data.season.js` → `meta.resourceNote` и `meta.today`: обновить текст под новое состояние.

Галочки внутри карточек (цели сессии, гранаты, чеклист) правкой файлов **не** ставятся — это
состояние на сервере, его отмечают игроки на сайте.

## Дизайн

Палитра снята с логотипа команды: неоново-розовый `#ff2e7e` и электрический фиолетовый
`#8a4bff` на почти чёрном с фиолетовым подтоном. Тема одна, живёт в `assets/css/theme.css`
как набор CSS-переменных — перекрасить весь сайт можно правкой одного файла.

Внутри плейбуков дополнительно работают цвета сторон: T — янтарный, CT — синий.

Шрифты вшиты локально (`assets/fonts`, woff2 с кириллицей): Oswald — заголовки,
Inter — текст, JetBrains Mono — технические подписи.

## Аккаунты и что где хранится

У каждого игрока свой вход: ник из списка плюс личный пароль. Состояние лежит на сервере
(Vercel Blob, приватный стор), поэтому синхронизируется между компом и телефоном
и не пропадает при чистке браузера.

Данные делятся на два вида, и делит их **сервер** — клиенту тут не доверяем:

| Что | Где | Ключи |
|---|---|---|
| **Личное** — выученные гранаты, освоенные правила, лестница внедрения | по документу на игрока | `nade-*`, `rule-*`, `lad-*` |
| **Командное** — заметки по картам, вето-планы, скаутинг, роли, счёт матчей, цели тренировок, чеклисты | один общий документ | всё остальное |

Логика разделения — `isPersonalKey()` в `lib/auth.js`. Хочешь перенести что-то из общего
в личное — правится там, в одном месте.

### Кто сколько отметил

Личные отметки закрыты друг от друга, но **количества видны всем** — иначе прогресс не с чем
сравнивать. Сводку отдаёт `api/team.js`: на каждого игрока только три числа (гранаты, правила,
лестница), без самих ключей. Что именно отметил другой, узнать нельзя.

Рисует сводку `assets/js/team-progress.js`, один модуль на обе страницы:

| Где | Карточка | По чему полоска |
|---|---|---|
| `index.html` → Обзор | «Готовность состава» | все 76 личных отметок |
| `pravila.html` → раздел 01 | «Кто сколько освоил» | 30 правил, под ником — лестница |

Обновляется сама: своя строка пересчитывается из локального состояния сразу по клику
(`Store.countByPrefix()` считает так же, как сервер), чужие подтягиваются после каждого
сохранения и при возврате на вкладку.

Кнопки в сайдбаре:

- **Бэкап** — выгружает текущее состояние в JSON (личное + командное, как видит этот игрок).
- **Сбросить моё** — стирает **только личные** отметки. Командные заметки и вето не трогает:
  это общий документ, и стирать его кнопкой одного игрока нельзя.
- **Выйти** — гасит сессию.
- **Печать / PDF** — раскрывает все вкладки и карточки, печатает в светлой вёрстке.

Индикатор под ником показывает состояние синхронизации: зелёный — всё сохранено,
жёлтый — отправляем, красный — нет связи. Неотправленное лежит в `localStorage`
и уходит на сервер, как только связь вернётся, так что отметки не теряются.

**Известное ограничение:** командный документ один на всех, атомарных транзакций нет.
Если двое одновременно правят *одно и то же* поле, победит тот, кто сохранил последним.
Разные поля сливаются корректно. Для шестерых это приемлемо.

## Хостинг

Задеплоено на Vercel: **https://ushibu-nogami-hq.vercel.app** — весь сайт закрыт паролем.

Проект: `khalezov89-gmailcoms-projects/ushibu-nogami-hq`. Деплой — `vercel deploy --prod`.

### Как устроен вход

Штатная защита паролем у Vercel на Pro — платный аддон Advanced Deployment Protection,
поэтому вход свой: `middleware.js` перехватывает запрос до кеша и либо пропускает
по сессии, либо отдаёт форму входа в фирменном оформлении.

- Закрыто **всё**: страницы, стили, скрипты и файлы с тактикой.
- Открыты только `assets/fonts/*`, `assets/img/*` (их использует форма входа)
  и `api/*` — функции проверяют сессию сами.
- Пароли хранятся как PBKDF2-SHA256, 210 000 итераций, у каждого своя соль.
  В открытом виде их нет нигде, включая переменные окружения.
- Сессия — подписанный HMAC-SHA256 токен в куке `HttpOnly` + `Secure` + `SameSite=Lax`, живёт 60 дней.
- Если `TEAM_USERS` или `AUTH_SECRET` не заданы — сайт закрывается (503), а не открывается.

### Переменные окружения

| Переменная | Что это |
|---|---|
| `TEAM_USERS` | JSON-массив `[{id, nick, hash}]` — состав и хеши паролей |
| `AUTH_SECRET` | секрет для подписи сессий; смена разлогинит всех |
| `BLOB_READ_WRITE_TOKEN` | доступ к приватному Blob-стору, проброшен автоматически |

### Добавить игрока или сменить пароль

Хеш считается функцией `hashPassword()` из `lib/auth.js`:

```bash
node --input-type=module -e "
  import('./lib/auth.js').then(async (A) => console.log(await A.hashPassword('новый-пароль')));
"
```

Полученный хеш добавить или заменить в `TEAM_USERS`, затем:

```bash
vercel env update TEAM_USERS production   # значение вводится в промпте
vercel deploy --prod
```

(`vercel env add/update` читает значение из промпта или stdin — передавать `ИМЯ=значение`
аргументом нельзя.) То же можно сделать в дашборде: Project → Settings → Environment Variables.

## Структура

```
index.html            pravila.html
middleware.js         вход по сессии (Vercel Routing Middleware, edge)
vercel.json           заголовки и кеш
lib/auth.js           пароли, сессии, состав, разделение личное/общее
api/
  login.js  logout.js         вход и выход
  state.js                    чтение и запись состояния
  team.js                     сводка готовности по составу
  _store.js                   доступ к Vercel Blob
assets/
  css/  tokens · theme · base · layout · components · print · fonts
  js/   data.season · data.playbook · data.rules · store · ui · team-progress · app · rules
  fonts/  Oswald · Inter · JetBrains Mono (woff2, latin + cyrillic)
  img/    logo.jpg
```

Скрипты подключены классическими тегами (не ES-модули) — именно поэтому страница
открывается напрямую с диска.
